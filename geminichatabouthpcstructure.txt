Understanding the Key Memory Columns
Once the column is visible, it helps to understand how it relates to the other data fields: 

Atlassian Support
VIRT (Virtual Image): The absolute total amount of memory a process is using. This includes code, data, shared libraries, and swapped-out memory.
RES (Resident Size): The actual physical RAM (in KiB) the process is occupying right now.
SWAP (Swapped Size): The portion of the process's data that has been kicked out of physical RAM and moved onto your hard drive or SSD. 

Atlassian Support
 +4
Formula Note: In modern Linux systems, top displays a dedicated metric for SWAP. In older Linux versions or separate flavors of Unix where the SWAP column isn't an option, you can approximate it by calculating: VIRT minus RES.

i cant use any swap
Wenn Ihr System trotz des Befehls keinen Swap-Speicher nutzt, liegt das bei diesem spezifischen Server an einer sehr effizienten Schutzfunktion des Linux-Kernels. 
Hier ist die direkte Erklärung, warum Sie aktuell keinen Swap erzwingen können und wie Sie das Verhalten bei Bedarf ändern:
Warum das System den Swap verweigert
Ihr Server verfügt über gigantische 13.133 GB komplett freien Arbeitsspeicher (13133G free).
Der Linux-Kernel ist so programmiert, dass er Daten nur dann auf die langsame Festplatte (Swap) auslagert, wenn der schnelle physische RAM knapp wird. Da Ihr RAM praktisch leer ist, blockiert das Betriebssystem jeden Versuch, Daten künstlich in den Swap zu verschieben, um die Systemperformance nicht grundlos auszubremsen. 
So können Sie die Swap-Nutzung trotzdem erzwingen
Falls Sie für Tests oder spezielle Anwendungen erzwingen möchten, dass das System aggressiver auslagert, müssen Sie den sogenannten swappiness-Wert des Kernels anpassen. 
Aktuellen Wert prüfen:
bash
cat /proc/sys/vm/swappiness
Verwende Code mit Vorsicht.
(Standardmäßig steht dieser Wert meist auf 60. Auf Servern mit viel RAM wird er oft von Administratoren auf 10 oder 1 gesetzt, um Swap fast komplett zu verbieten). 
Swap-Aktivität maximieren (Temporär):
Erhöhen Sie den Wert auf das Maximum (100), um dem Kernel zu befehlen, Swap-Speicher genauso gleichwertig wie den echten RAM zu behandeln:
bash
sudo sysctl vm.swappiness=100
Verwende Code mit Vorsicht.
 
Den Swap komplett neu starten:
Manchmal "hängt" die Zuweisung. Sie können den Swap-Speicher einmal komplett leeren und neu einhängen (Achtung: Dies kann bei 2 GB Belegung ein paar Sekunden dauern):
bash
sudo swapoff -a && sudo swapon -a
Verwende Code mit Vorsicht.
 
Was Sie stattdessen prüfen sollten
Da Ihr Hauptproblem die extrem hohe Systemlast (load average: 85.59) und nicht der Speicher ist, wird mehr Swap-Nutzung die Leistung des Servers nicht verbessern.
